Documentation / Getting started

BCSFE API

Edit save files, store backups and issue account copies from your own application.

Base URL

https://battle-cats-save-file-editor-api.vercel.app

Use this origin as API_URL in the examples below. Requests and responses use JSON unless an endpoint specifies a file.

Authentication

Authorization: Bearer YOUR_API_KEY

Backup and copy endpoints use TEMPLATE_API_KEY. Editor and account endpoints use EDITOR_API_KEY, falling back to the template key when a separate editor key is not configured. Keys must contain at least 32 characters.

Documentation / Backups & copies

Backups & copies

Store a save once, keep its template ID, and reuse it through HTTP.

These endpoints use TEMPLATE_API_KEY. Stored templates are private, encrypted JSONBin records. Configure JSONBIN_API_KEY on the server; clients only need the template API key.

1. Store a backup

POST/v1/templates
curl -X POST "$API_URL/v1/templates" \
  -H "Authorization: Bearer $TEMPLATE_API_KEY" \
  -F "file=@original.save" \
  -F "country_code=auto" \
  -F "name=Starter account"

Alternatively, send JSON with save_base64, country_code and name. Set the region to auto to detect it from the file checksum; omitting it defaults to kr.

The 201 response contains these fields, plus the file size, SHA-256 digest and creation time:

{
  "success": true,
  "template_id": "YOUR_TEMPLATE_ID",
  "name": "Starter account",
  "country_code": "kr",
  "game_version": 150500,
  "clone_ready": true
}

Save template_id in your application's database. The stored original is immutable. clone_ready means the save passed the binary round-trip check needed for copying.

2. Download the original

GET/v1/templates/{template_id}/download
curl "$API_URL/v1/templates/$TEMPLATE_ID/download" \
  -H "Authorization: Bearer $TEMPLATE_API_KEY" \
  -o original.save

Returns the exact stored bytes as application/octet-stream. Restoring them to the game requires your existing save-import or transfer workflow.

3. Create an account copy

POST/v1/templates/{template_id}/clones
curl -X POST "$API_URL/v1/templates/$TEMPLATE_ID/clones" \
  -H "Authorization: Bearer $TEMPLATE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"order_id":"order-1001"}'

The API creates separate account credentials from the saved state, synchronizes managed items and requests transfer codes. The original template remains unchanged. A successful 201 response includes:

{
  "success": true,
  "persisted": true,
  "retry_safe": false,
  "order_id": "order-1001",
  "transfer_code": "ISSUED_TRANSFER_CODE",
  "confirmation_code": "ISSUED_CONFIRMATION_CODE",
  "attempt_id": "ATTEMPT_ID",
  "recovery_id": "RECOVERY_ID",
  "issuance_id": "ISSUANCE_ID",
  "status": "issued"
}

Reserve each order in your application's database before calling this endpoint. order_id is an audit label, not a deduplication guarantee. The vending backend example demonstrates persistent order reservation and uncertain-result handling.

Pass each returned next_cursor as the next request's cursor. Continue until it is null, including when a filtered page is empty. Listing template IDs does not include their full metadata; fetch each template by ID when needed.

Recovery after an unconfirmed request

An unconfirmed copy returns 502, retry_safe: false and available recovery references or Base64 save data. Preserve that response and review the attempt before issuing another request. If persisted is false in a successful response, store the returned codes yourself.

Return a backup without storing it

POST /v1/backups accepts the same multipart or JSON input as template creation and returns the original file directly. It does not create a JSONBin record. Use POST /v1/templates when the file must remain available for later download or copying.

Documentation / File editing

File editing

Send a save file and a batch of typed operations. Receive the edited file and its original backup.

POST/v2/save/edit
{
  "country_code": "kr",
  "save_base64": "BASE64_OF_SAVE_FILE",
  "operations": [
    { "action": "items.xp", "args": { "value": 99999999 } }
  ]
}

Send Content-Type: application/json and your editor Bearer token. Browse the action schemas for required arguments, ranges and defaults.

Response

The JSON response contains save_base64 for the edited file, backup_base64 for the original, changes, change_count and sha256. Set output to "file" to receive the edited file directly.

Operations run on a copy and are applied atomically. The API serializes and reparses the result, checks the checksum and verifies that edited fields survived serialization. A failed batch is not returned as a partially successful edit.

Inspect and export

POST /v2/save/inspectInspect a save without editing it.
POST /v2/save/exportExport editable save state to JSON.
POST /v2/save/importImport JSON state and validate the resulting save.
POST /v2/save/downloadReturn a validated file.

Metadata and source compatibility

Ordinary file edits use the vendored BCSFE parser and offsets. Operations that need cat or map data use versioned game metadata. See /v2/metadata/prepare and the relevant action schema before building a batch.

Actions with respect_maxima use BCSFE's recommended limits by default. Setting it to false does not bypass the field's integer range. Cat IDs and array indexes are zero-based; displayed levels, forms and crowns follow each action's schema.

Documentation / Accounts & transfers

Accounts & transfers

Receive a save, upload an edited account or request new credentials.

Receive a save

POST/v2/save/from-transfer
{
  "transfer_code": "YOUR_TRANSFER_CODE",
  "confirmation_code": "YOUR_PIN",
  "country_code": "kr",
  "game_version": 150500
}

Receiving a transfer consumes the supplied code. Keep the returned save_base64; it includes refreshed credentials. The received original is also returned as backup_base64.

Account endpoints

POST /v2/save/uploadUpload a save and issue transfer codes.
POST /v2/account/newCreate account credentials and synchronize managed items. Upload separately to issue codes.
POST /v2/account/convert-regionChange region and create an account for it. Include target_country_code.
POST /v2/account/upload-itemsUpload item metadata.

To issue copies from a reusable stored save, use the backup and copy endpoints.

Unconfirmed results

When an account request is not confirmed, the API returns available recovery files and retry_safe: false. Preserve those files before reviewing the attempt. Account creation is not retried automatically after an authentication failure.

Live account creation and in-game acceptance require separate verification. ADB/root device operations and terminal-only controls are outside this hosted API.

Legacy integrations

POST /edit and POST /info remain available with strict validation and authentication. Both receive a transfer and consume its code.

Documentation / Metadata & configuration

Metadata & configuration

Prepare versioned game tables and inspect the defaults used by edit operations.

Prepare game metadata

Cat selection by name, level limits, evolution, talents and some map operations require game tables for the save's region and version. File parsing uses the vendored BCSFE source; game tables are separate versioned data.

POST/v2/metadata/prepare
{ "country_code": "kr", "game_version": 150500 }

Send the editor Bearer key. 150500 represents game version 15.5.0. The response reports requested_version, resolved_version, exact_match, downloaded, source and archive_source. Check the selected version when an exact match was unavailable.

Available versions and cache

GET /v2/metadata/versionsList available metadata versions.
DELETE /v2/metadata/cacheRemove downloaded metadata for the requested region and optional version. Stored backup templates are separate.
GET /v2/editor/configRead editor defaults and maximum values.

Vercel's temporary filesystem is not a persistent shared cache. Another function instance or a later deployment may need to prepare the data again. A metadata failure is reported as an error; it does not confirm an edit.

Editing options

Set action arguments such as respect_maxima, selectors and reset flags in each request. The configuration endpoint is read-only; it does not change every preference from the desktop terminal editor.
