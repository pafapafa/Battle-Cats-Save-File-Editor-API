Documentation / Getting started

Getting started

Read, edit and back up Battle Cats save files over HTTP.

Authentication

Send your editor key in the Authorization header. Backup and copy endpoints use the template key. If a separate editor key is not configured, the template key works for both.

Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

Use to authorize requests made from this page.

Edit a file

Encode the file as Base64 and include the operations you want to apply.

POST/v2/save/edit
{
  "country_code": "kr",
  "save_base64": "BASE64_OF_SAVE_FILE",
  "operations": [
    { "action": "items.xp", "args": { "value": 99999999 } }
  ]
}

The response contains save_base64 for the edited file, backup_base64 for the original, and changes for the fields that changed. Set output to "file" to receive the edited file directly.

Back up a file

Use Backups to upload a file without writing a request. For API integrations, send a multipart file to POST /v1/templates. Set country_code to auto to detect the region.

curl -X POST "$API_URL/v1/templates" \
  -H "Authorization: Bearer $TEMPLATE_API_KEY" \
  -F "file=@original.save" \
  -F "country_code=auto" \
  -F "name=Before editing"

Limits and errors

Save fileUp to 1 MiB
Request bodyUp to 2 MiB
Operations per request1–100
400 / 401Invalid request / missing or invalid API key
422Invalid edit, unsupported data or a failed save check
502 / 503Unconfirmed remote result / unavailable configuration or storage

File edits are checked by saving and reading the result again. This verifies persistence, not acceptance by the game server. ADB/root device operations are outside this hosted API.

Older /edit and /info integrations remain available with stricter inputs and authentication. Both receive a transfer and consume its code.

Documentation / Accounts & transfers

Accounts & transfers

Receive a save, issue transfer codes or create an account from a saved template.

Receive a save

POST/v2/save/from-transfer
{
  "transfer_code": "YOUR_TRANSFER_CODE",
  "confirmation_code": "YOUR_PIN",
  "country_code": "kr",
  "game_version": 150500
}

Receiving a transfer consumes the supplied code. Keep the returned save_base64; it includes refreshed credentials. The received original is also returned as backup_base64.

Create a copy from a backup

Select Create copy beside a saved backup. The API creates a new account from the saved state and requests transfer codes. The stored backup is preserved.

POST/v1/templates/{template_id}/clones
{ "order_id": "your-unique-order-reference" }

A successful response contains the transfer code, confirmation code and recovery record. Use a persistent order reservation in automated clients: the order reference alone does not prevent concurrent duplicate requests.

Other account endpoints

POST /v2/save/uploadUpload a save and issue transfer codes.
POST /v2/account/newCreate account credentials and synchronize managed items. Upload separately to issue codes.
POST /v2/account/convert-regionChange region and create an account for it. Include target_country_code.
POST /v2/account/upload-itemsUpload item metadata.

Interrupted requests

When an account request is not confirmed, the API returns available recovery files and retry_safe: false. Preserve those files and review the attempt before issuing another request. Account creation is never retried automatically after an authentication failure.

Real account acceptance and in-game behavior still require verification. The API reports the server result it receives.
